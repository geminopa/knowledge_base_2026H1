# パワーストラクチャの作り方

作り方自体は難しくない。役職を階層ごとに書き出し、関係のある相手を洗い出し、関係の強さを記号で書き込むだけの5ステップ。表形式で作れるので、専用の作図ツールは不要。

## 作成手順

| 手順 | やること |
|---|---|
| 1 | 取引先の役職・役割を一覧にする（代表取締役を最上位に、下にいくほど現場に近い役職・役割になるよう並べる） |
| 2 | 自社側の人員を同様に一覧にする（その取引先に関わるメンバーを、責任の重い役職を上にして並べる） |
| 3 | 関係のある相手を洗い出す（社内の上下関係、取引先社内の上下関係、自社・取引先をまたぐ関係のすべてが対象） |
| 4 | それぞれの関係に〇△×を書き込む（社内の関係にも書き込む） |
| 5 | 表全体を眺めて、偏り・空白・リスクを分析する |

関係性を表す記号は、次の3段階で十分。

| 記号 | 意味 | 目安 |
|---|---|---|
| 〇 | 良好 | 信頼されており、率直に相談や情報交換ができる |
| △ | 普通・浅い | 面識はあるが、深い話まではできていない |
| × | 課題あり | 関係が悪い、または接点がほとんどない |

## 具体例

自社を左列、取引先を右列にし、同じ階層を同じ行に並べる（上下はあくまで各社内での役職の重さを表し、自社と取引先の優劣ではない）。

| 階層 | 自社 | 自社内の関係 | 取引先 | 取引先内の関係 |
|---|---|---|---|---|
| 最上位 | 代表取締役 | ― | 代表取締役 | ― |
| | 取締役 | 〇（代表取締役と） | 取締役 | 〇（代表取締役と） |
| | 部長 | △（取締役と） | 部長・決裁者 | △（取締役と） |
| | マネージャ | 〇（部長と） | マネージャ・窓口 | 〇（部長と） |
| | PM | 〇（マネージャと） | 担当者 | 〇（マネージャと） |
| | PL | 〇（PMと） | ― | ― |
| 最下位 | メンバー | △（PLと） | ― | ― |

自社・取引先をまたぐ関係（階層がずれることも多い）は別の表にまとめる。

| 自社 | 取引先 | 関係 |
|---|---|---|
| PM | マネージャ・窓口 | 〇 |
| PM | 部長・決裁者 | △ |
| PL | 担当者 | 〇 |
| メンバー | マネージャ・窓口 | × |

表ができたら、以下のような読み取り方で分析する。

- 決裁者（部長）との関係が△で、しかもPMひとりに依存している → 他のメンバーとの接点も作れないか検討する
- 窓口のマネージャとはPMが〇である一方、メンバーとは×で、意思疎通に課題がある → 定例会にメンバーも同席する機会を増やす
- 担当者とはPLが〇で、現場の情報はPL経由で取れている → 引き続きPL経由の関係を維持する
- 自社内でも取締役-部長間、PL-メンバー間が△になっている → 社外だけでなく社内の情報伝達も見直す

エンジニアの立場でも、要件のヒアリング時に最終判断者を確認したり、担当交代の際の引き継ぎ資料として使ったりできる。

## コツ

- まずは担当している取引先のひとつで、簡単な表を作ってみるところから始める
- チームで一緒に作ると、同じ相手でも人によって〇△×の評価が違うことに気づける
