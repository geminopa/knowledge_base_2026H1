# Skillsは何のために使うのか

「毎回同じ指示をコピペしている」「`CLAUDE.md` の一部が、事実の記述ではなく手順書のようになってきた」——このどちらかに当てはまったら、Skillを作るタイミング。

## CLAUDE.mdとの違い

`CLAUDE.md` も同様に指示を覚えさせられるが、Skillには2つの利点がある。

| | `CLAUDE.md` | Skill |
|---|---|---|
| 読み込まれるタイミング | 毎回の会話開始時、常に読み込む | 呼び出された（使われた）ときだけ読み込む |
| コンテキストへの負荷 | 内容が増えるほど毎回重くなる | 使わない限りほぼ負荷がない |
| 起動方法 | 常に効いている | `/{command_name}` で手動、または内容が合えばClaudeが自動で使う |

長い手順書を `CLAUDE.md` に書くと、関係ない作業のときも毎回読み込まれてしまう。Skillにしておけば、必要なときだけ読み込まれる。

## 具体例: CLAUDE.mdからSkillへの切り出し

**Before（CLAUDE.mdに書いていた場合）**

```markdown
# バグ報告を受けたときの調査手順
1. 再現手順を実際になぞる
2. ログを`storage/logs/`から該当時刻分を確認する
3. 影響範囲を洗い出す
4. 原因・対応方針をまとめて報告する
```

この手順は「バグ調査のとき」にしか使わないのに、毎回の会話で読み込まれてしまう。

**After（Skillに切り出す）**

`.claude/skills/investigate-bug/SKILL.md` に同じ内容を移すと、バグ調査で `/investigate-bug` と打ったとき、またはそれに近い相談をしたときだけ読み込まれる。

## コツ

- 「3回以上同じ指示を打った」「`CLAUDE.md` が200行に近づいてきた」がSkill化の目安
- 知識（〇〇のルール、〇〇の仕様）ではなく、手順（〇〇したいときの一連の作業）の方がSkillに向いている
- 自動発動させたい場合は `description` を具体的に書く。ここが曖昧だとClaudeが自動で使ってくれない
