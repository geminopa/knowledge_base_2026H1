# Skillsを使う上での注意点

便利な反面、いくつか知らずに使うとハマるポイントがある。

## 注意点

| 注意点 | 内容 |
|---|---|
| 常に少しコストがかかる | Skillの本文は使うまで読み込まれないが、`description`（説明文）自体は毎回の会話で常に読み込まれる。数が多いと積み重なる |
| 説明文の質が自動発動を左右する | `description` が曖昧だと、使ってほしい場面でClaudeが自動発動してくれない |
| `allowed-tools` は誰が書いても効いてしまう | 共有リポジトリのSkillに書かれた `allowed-tools` は、信頼していない相手が書いたものでもそのまま有効になる。中身を確認してから使う |
| 埋め込みコマンドも権限ルールの対象 | `` !`コマンド` `` で埋め込む実行結果も、通常のコマンド実行と同じ許可・拒否ルールの対象になる。denyに該当すればSkillごと止まる |
| 長すぎると読み込みが重い | 1ファイルの目安は500行以内。詳しい内容は別ファイルに分けてSKILL.mdから参照する形にする |

## 具体例: ありがちな失敗

```markdown
---
name: cleanup
description: 掃除する
allowed-tools: Bash(rm -rf *)
---
不要なファイルを削除してください。
```

- `description` が「掃除する」では曖昧すぎて、意図しない場面でClaudeが自動発動する可能性がある
- `allowed-tools: Bash(rm -rf *)` は削除範囲が広すぎる。共有リポジトリに置くと、他の人がこのSkillを実行したときに想定外の削除が起きうる

**改善例**

```markdown
---
name: cleanup-tmp
description: storage/tmp配下の一時ファイルを削除する。「一時ファイルを掃除して」と言われたときに使う
allowed-tools: Bash(rm -rf ./storage/tmp/*)
---
storage/tmp配下の一時ファイルを削除してください。
```

## コツ

- 使っていないSkillが増えてきたら定期的に見直し、不要なものは削除する
- 複数人で使うリポジトリでは、Skillを追加・変更したらレビューを通す運用にすると安全
- まずは「読み取り専用の確認作業」のようなリスクの低いSkillから作り始めるとよい
