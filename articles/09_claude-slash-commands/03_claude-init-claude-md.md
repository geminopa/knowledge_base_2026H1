# /init と CLAUDE.md で、プロジェクトの前提を毎回説明しなくて済むようにする

Claude Codeは毎回まっさらな状態で会話を始める。「テストは `phpunit` で実行」「コメントは日本語で」のような決まりを毎回説明しているなら、`CLAUDE.md` に書いておくと自動で読み込まれる。

## 使い方

1. リポジトリのルートで `/init` を実行する
2. Claude Codeがコードを解析し、ビルド・テストコマンドや規約を書いた `CLAUDE.md` のたたき台を作る
3. 中身を確認し、Claudeが自力では気づけない決まりを追記する
4. 以降の追記・修正は `/memory` から編集できる

すでに `CLAUDE.md` がある場合、`/init` は上書きせずに改善案を出す。

## 具体例: 追記すると効果が大きい内容

```markdown
# プロジェクトのルール
- テスト実行: `./vendor/bin/phpunit`（DBはローカルのMySQL 8.4を使う）
- コーディング規約は PSR-12 に準拠する
- 日付は必ず `Carbon` 経由で扱う（直接 `new DateTime()` しない）
```

## 置き場所の使い分け

| ファイル | 誰に効くか | 書く内容の例 |
|---|---|---|
| `./CLAUDE.md`（または `./.claude/CLAUDE.md`） | チーム全員（gitで共有） | ビルド手順、コーディング規約 |
| `./CLAUDE.local.md` | 自分だけ・このプロジェクトだけ | 自分の検証環境のURL（`.gitignore` に追加する） |
| `~/.claude/CLAUDE.md` | 自分だけ・全プロジェクト | 「回答は日本語で」など個人の好み |

## コツ

- 1ファイル200行以内が目安。長すぎると読み込み量が増え、指示が守られにくくなる
- 「きちんとしたコードを書く」のような曖昧な指示より、「関数は50行以内」のように具体的に書くほうが守られやすい
- 読み込まれているかどうかは `/context` の **Memory files** で確認できる
