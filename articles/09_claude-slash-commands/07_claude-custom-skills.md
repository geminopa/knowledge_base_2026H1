# 自作のスラッシュコマンド（skill）で、チームの定型作業を共通化する

「リリース前チェックを同じ手順で」「障害報告を同じ書式で」のように毎回同じ指示を出しているなら、自作のスラッシュコマンドにしておくと `/名前` だけで呼び出せる。現在は **skill** という形式で作るのが推奨されている。

## 作り方

`.claude/skills/<コマンド名>/SKILL.md` を作るだけ。ディレクトリ名がそのままコマンド名になる。

```markdown
---
name: release-check
description: リリース前のセルフチェックを行う
disable-model-invocation: true
---

以下の観点で現在のブランチをチェックし、結果を表にまとめてください。
1. マイグレーションファイルにロールバック処理があるか
2. 設定ファイルに開発環境の値が残っていないか
3. TODO / FIXME コメントが残っていないか

対象: $ARGUMENTS
```

呼び出し方:

```text
/release-check src/order/
```

`$ARGUMENTS` の部分に `src/order/` が入る。

## 置き場所

| 場所 | 使える範囲 |
|---|---|
| `.claude/skills/` | そのリポジトリだけ。コミットすればチーム全員が使える |
| `~/.claude/skills/` | 自分だけ・全プロジェクト |

以前の形式である `.claude/commands/<名前>.md` も引き続き使える。

## 便利な設定（frontmatter）

| 項目 | 効果 |
|---|---|
| `description` | 何をするコマンドか。Claudeが自動で使うかどうかの判断にも使われる |
| `disable-model-invocation: true` | 人が呼んだときだけ動く。デプロイなど副作用のある操作に付ける |
| `allowed-tools` | 実行中に確認なしで使えるツールを指定する（例: `Bash(git *)`） |

## コツ

- 最初は「毎週3回以上出している指示」から作ると効果を実感しやすい
- 手順の中に `` !`git diff HEAD` `` のように書くと、コマンドの実行結果を埋め込んだ状態でClaudeに渡せる
