# /clear と /compact の使い分け

どちらも「会話が長くなったとき」に使うが、目的が違う。**話題を変えるなら `/clear`、同じ作業を続けるなら `/compact`** と覚えておけばよい。

## 違い

| | `/clear` | `/compact` |
|---|---|---|
| やること | 会話を空にして新しく始める | これまでの会話を要約に置き換える |
| 前の文脈 | 引き継がない | 要約として引き継ぐ |
| 向いている場面 | 別タスクに切り替えるとき | 同じタスクを続けたいが、会話が長くなったとき |
| 別名 | `/reset`、`/new` | なし |

## 具体例

**例1: 別の不具合調査に移る → `/clear`**

```text
（ログイン画面のバグ修正が完了）
/clear
帳票出力でCSVが文字化けする件を調べて
```

前の話題が残っていると、無関係な前提に引っ張られた回答になりやすい。

**例2: 長いリファクタリングの途中 → `/compact`**

```text
/compact 変更したファイル一覧と、残っているTODOを中心に残して
```

引数で「何を残してほしいか」を指定できる。指定しないと、要約で重要な細部が落ちることがある。

## 注意点・コツ

- `/clear` しても前の会話は保存されている。間違えて消した場合は `/resume` で戻れる
- `/clear 名前` のように名前を付けると、離れる会話にその名前が付き、後で `/resume` から探しやすくなる
- 「最近、前に言ったことを忘れる」「回答がずれる」と感じたら、`/context` で使用量を確認してから、どちらを使うか判断する
