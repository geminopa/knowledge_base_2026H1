# そもそもSkillsとは何か

Skillsとは、Claude Codeに独自の指示・手順を追加できる仕組み。`SKILL.md` という1つのファイルを作るだけで、Claudeが使える手札（ツールキット）に自作の手順を1つ追加できる。

## 何ができるようになるか

| できること | 説明 |
|---|---|
| 独自コマンド化 | `/{command_name}` と打つだけで、決まった手順をClaudeに実行させられる |
| 自動発動 | 人が呼ばなくても、会話の内容に合っていればClaudeが自分から使う |
| チーム共有 | リポジトリにコミットすれば、クローンした人全員が使える |

以前は `.claude/commands/{command_name}.md` という形式があったが、現在は同じ役割をより柔軟にした **skill** 形式（`.claude/skills/{command_name}/SKILL.md`）で作るのが基本になっている。

## 具体例: 最小のSkill

```markdown
---
name: release-check
description: リリース前のセルフチェックを行う
---

以下の観点で現在のブランチをチェックし、結果を表にまとめてください。
1. マイグレーションファイルにロールバック処理があるか
2. 設定ファイルに開発環境の値が残っていないか
3. TODO / FIXME コメントが残っていないか
```

このファイルを `.claude/skills/release-check/SKILL.md` として保存すると、`/release-check` で呼び出せるようになる。ディレクトリ名がそのままコマンド名になる。

## 置き場所

| 場所 | 使える範囲 |
|---|---|
| `.claude/skills/` | そのリポジトリだけ。コミットすればチーム全員が使える |
| `~/.claude/skills/` | 自分だけ・全プロジェクト |

## コツ

- ファイル冒頭の `---` から始まるYAML部分が設定（frontmatter）、それ以降がClaudeへの指示文
- まずは中身がシンプルな1つのSkillを作って動かしてみると、仕組みが理解しやすい
- 「何のために使うか」「どんな使い方があるか」「注意点」は続く記事で扱う
