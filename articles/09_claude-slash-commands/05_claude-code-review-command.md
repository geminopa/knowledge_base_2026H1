# /code-review コマンドのオプションを使い分ける

人にレビューを依頼する前の一次チェックとして使えるのが `/code-review`（別名 `/review`）。レビューの深さや対象を引数で指定できる。運用の考え方は「Claude Codeにコードレビューを下読みしてもらう使い方」（`07_ai-tools/01_claude-code-review-first-pass.md`）を参照。本記事ではコマンドの使い方に絞る。

## 基本形

```text
/code-review [深さ] [オプション] [対象]
```

| 指定 | 意味 |
|---|---|
| 引数なし | 現在の差分（未コミットの変更）をレビューする |
| `low` / `medium` | 指摘を確度の高いものに絞る。件数は少ない |
| `high` 〜 `max` | 広く見る。確度の低い指摘も含まれる |
| `--fix` | 指摘内容をそのまま修正に反映する |
| `--comment` | GitHubのPR（GitLabのMR）に指摘をコメントとして投稿する |
| PR番号・ブランチ名・パス | レビュー対象を指定する |

## 具体例

```text
/code-review                 ← コミット前に、今の差分をざっと確認
/code-review high            ← リリース前など、念入りに見てほしいとき
/code-review medium --fix    ← 確度の高い指摘だけ自動で直す
/code-review 123             ← PR #123 をレビュー
/code-review src/billing/    ← 特定ディレクトリだけ見る
```

## 注意点・コツ

- `--fix` は差分を直接書き換える。先にコミットしておくか、修正後に `git diff` で必ず確認する
- `--comment` はPR上に公開される。チームのルール上問題ないか確認してから使う
- 指摘は「バグの可能性」が中心。仕様として正しいかどうかは自分で判断する
