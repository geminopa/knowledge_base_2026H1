# 境界値テストの確認観点

「境界値テスト」というと最小値・最大値だけを思い浮かべがちだが、実際に不具合が出やすい観点は他にもある。観点ごとに「どういうときに実施すべきか」を判断できるようにしておく。

## 観点一覧

| 観点 | 実施すべきケース |
|---|---|
| 数値の上下限 | 入力項目や集計処理に、数値の上限・下限が仕様として決まっているとき |
| 0・空文字・null・未入力の違い | 数値/文字列項目で「未入力」と「0」「空文字」が別扱いになりうるとき |
| 比較演算子の境界（`>=`と`>`のズレ） | 「〇件以上」「〇件を超えたら」のように比較演算子で条件分岐しているとき（実装ミスが起きやすい） |
| 日付の境界 | 月末・月初、年またぎ、うるう年をまたぐ集計・バッチ処理があるとき |
| 文字数・桁数の境界 | DBのカラム長やフォームの`maxlength`が決まっている入力項目があるとき |
| 件数0件・配列が空 | 一覧表示・集計・ループ処理で、対象データが0件になりうるとき |

## 観点ごとのテストケース例

### 1. 数値の上下限

「注文数は1〜100個まで」のように、仕様書に数値の範囲が明記されているときに実施する。

| No | 入力値 | 期待結果 |
|---|---|---|
| 1 | 0 | エラー（範囲外） |
| 2 | 1 | 登録できる（下限） |
| 3 | 100 | 登録できる（上限） |
| 4 | 101 | エラー（範囲外） |

### 2. 0・空文字・null・未入力の違い

「在庫数」「メモ欄」のように、数値・文字列で「未入力」を別途考慮する必要がある項目があるときに実施する。

| No | 入力値 | 期待結果 |
|---|---|---|
| 1 | 未入力のまま送信 | 必須エラー、またはデフォルト値が入る（仕様通りか確認） |
| 2 | `0` を入力 | 未入力とは区別され、正常に0として登録される |
| 3 | 半角スペースのみ | 空文字扱いになるか、値ありと判定されるか確認する |

### 3. 比較演算子の境界（`>=`と`>`のズレ）

「在庫が10件『以上』で警告表示」のように、仕様の「以上」「より大きい」「未満」といった言葉を `>=` `>` `<` のどれで実装したかによって、境界の値（この例では10件）の結果が変わってしまう。実装ミスはレビューでも見逃されやすいので、境界値そのものを必ずテストする。

| No | 入力値（在庫数） | 期待結果 |
|---|---|---|
| 1 | 9件 | 警告表示されない |
| 2 | 10件 | 警告表示される（境界ちょうど） |
| 3 | 11件 | 警告表示される |

### 4. 日付の境界

月次バッチ、集計処理、キャンペーン期間の判定など、日付をまたぐ処理があるときに実施する。

| No | 条件 | 期待結果 |
|---|---|---|
| 1 | 2028/2/29（うるう年）を集計対象日にする | エラーにならず正しく集計される |
| 2 | 12/31 23:59:59 に登録したデータ | 当月の集計に含まれる |
| 3 | 1/1 00:00:00 に登録したデータ | 翌月（新年）の集計に含まれ、前月には含まれない |

### 5. 文字数・桁数の境界

DBのカラム定義（例: `VARCHAR(50)`）や画面の`maxlength`が決まっている入力項目があるときに実施する。マルチバイト文字はバイト数と文字数がずれるため要注意。

| No | 入力値 | 期待結果 |
|---|---|---|
| 1 | 50文字ちょうどの日本語文字列 | 登録できる |
| 2 | 51文字の日本語文字列 | エラー、または51文字目が切り捨てられる（仕様通りか確認） |
| 3 | 絵文字・機種依存文字を含む文字列 | 文字化けせず登録・表示できる |

### 6. 件数0件・配列が空

一覧画面や集計バッチで、対象データが1件もない状態になりうるときに実施する。

| No | 状況 | 期待結果 |
|---|---|---|
| 1 | 検索条件に一致するデータが0件 | エラーにならず「該当データなし」等の表示になる |
| 2 | 集計対象データが0件のままバッチを実行 | 0件・0円などとして正しく出力され、異常終了しない |

## コツ

- 観点は「仕様書に書かれている数値・条件の前後1」を機械的に洗い出すだけでも、抜け漏れがかなり減る
- 実装コードの比較演算子（`>=` `>` `<=` `<`）を先に確認すると、どの境界を狙えばよいかが分かりやすい
