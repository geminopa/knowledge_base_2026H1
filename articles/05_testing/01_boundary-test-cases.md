# 境界値テストで見落としがちなケース

「境界値テスト」というと最小値・最大値だけを思い浮かべがちだが、実際に不具合が出やすいのはもう少し細かいところ。

- **0・空文字・null・未入力の違い**
  数値項目で「0」と「未入力」を別扱いにしているか。文字列項目で「空文字」と「null」を同じ扱いにしているか。仕様書に明記されていないことが多く、抜けやすい。
- **ちょうど境界の前後1**
  「10件以上で警告」なら、9件・10件・11件の3パターンは必ず確認する。`>=` と `>` の実装ミス（off-by-one）はレビューでも見逃されやすい。
- **日付の境界**
  月末・月初、うるう年の2/29、年またぎ（12/31→1/1）は集計処理やバッチでバグが出やすい定番ポイント。
- **文字数・桁数の境界**
  DBのカラム長ぴったりの文字数を入れた時（マルチバイト文字だとバイト数と文字数がずれる点も注意）。
- **配列・件数0件のケース**
  一覧画面や集計処理で「0件」の時にエラーにならず正しく空表示されるか。

境界値は「仕様書に書かれている数値の前後1」を機械的に洗い出すだけでも、抜け漏れがかなり減る。
