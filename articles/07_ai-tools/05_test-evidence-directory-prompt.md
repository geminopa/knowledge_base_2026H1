# テスト仕様書を読ませて、エビデンス格納ディレクトリを自動生成するプロンプト

単体テストのエビデンス格納先は「シート番号 / テストケースNo.」のようにディレクトリを分けて運用することが多い。件数が多い案件だと、この空ディレクトリを手作業で作るのは地味に手間がかかる。テスト仕様書（Excel）をAIに読ませれば、件数を数える作業ごと任せられる。

## 前提となる運用ルール

| シート | テストケースNo. | 格納先ディレクトリ |
|---|---|---|
| 1番目のシート | No.1 | `1/1` |
| 1番目のシート | No.3 | `1/3` |
| 2番目のシート | No.5 | `2/5` |

「シート＝観点」「シートの中に複数のテストケース」という構成であれば、案件が変わっても同じルールで統一できる。

## 使うプロンプト

```
以下のテスト仕様書（Excelファイル）を読み込み、シートごとのテストケースNo.を
確認した上で、テストエビデンス格納用のディレクトリを作成してください。

- テスト仕様書のパス: {ここにファイルパスを指定}
- 対象シート: テストケースの一覧が入っているシートのみ対象にする
  （表紙・目次・改訂履歴などのシートは除外する）
- シート番号の付け方: シート名ではなく、ブック内でのシートの並び順を
  1から数えたものを「シート番号」とする
- テストケース番号の拾い方: 各シートの「No.」列（テストケース番号が
  入っている列）に実際に記載されている番号をそのまま使う
  （欠番がある場合は欠番のままにし、存在しない番号のディレクトリは作らない）
- ディレクトリ構成のルール: `シート番号/テストケース番号` の階層にする
  - 例: 1番目のシートのテストケースNo.3 → 1/3
- 格納先ルート: {ここにパスを指定、例: ./evidence}
- 既存のディレクトリがあれば壊さず、不足している分だけ追加で作成する
- 作成前に「シートごとのテストケース数・番号の一覧」を表示して確認を取り、
  問題なければディレクトリを作成し、最後にディレクトリツリーを表示してください
```

パスとルート先の2箇所だけ書き換えれば、どの案件でもそのまま使い回せる。

## 注意点

- **シート番号は「並び順」で数える**。シート名が「機能A」「機能B」のように連番になっていないことが多いため、シート名をそのままディレクトリ名にしないよう明記しておく。
- **欠番をそのまま欠番として扱う**よう指定する。「1件目から連番でN件」と決め打ちにすると、テスト仕様書側でNo.が飛んでいた（例: No.4を欠番にして削除した）場合にズレたディレクトリができてしまう。
- **列名がイレギュラーだと拾い漏れる**。「No.」ではなく「項番」「No」など表記がゆれている仕様書もあるため、実際の見出し名が分かっていればプロンプトに書き足しておくと精度が上がる。
- **作成前に一覧を出して確認を取る**ステップを必ず入れる。別の列（手順No.など）を件数として誤認識していないか、その場で気づける。
- **1シートに複数の観点が混在している**仕様書では、「シート＝1観点」という前提が崩れる。その場合は「テスト区分列が変わってもシート単位でのみ番号を振る」のように前提を一言添える。

## コツ

- このプロンプトはテンプレートとして手元に保存しておき、案件ごとに「パス」と「格納先ルート」の2箇所だけ書き換えて使う
- 初回はエビデンス格納先を仮のディレクトリにして試し、意図通りの階層になっているかを確認してから本番の格納先に向けて実行すると安全
