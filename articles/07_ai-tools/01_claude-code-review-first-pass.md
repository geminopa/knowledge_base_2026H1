# Claude Codeにコードレビューを下読みしてもらう使い方

人にレビュー依頼を出す前に、Claude Codeに一次チェックしてもらうとレビューコストを下げられる。

- **使い方**
  差分を作った状態で「この変更をレビューして、バグの可能性・命名・重複コードの観点で指摘して」と依頼する。`/code-review` のようなレビュー用のコマンドが用意されている場合はそれを使ってもよい。
- **向いていること**
  タイポ、Nullチェック漏れ、命名の一貫性、似たコードの重複、単純なロジックミスなど「機械的に気づける」観点の指摘は精度が高い。
- **向いていないこと**
  「この設計が業務要件に本当に合っているか」「お客様の意図と合っているか」といった仕様理解が必要な判断は、こちらの背景情報を与えないと的外れになりやすい。
- **運用のコツ**
  人へのレビュー依頼の代わりにするのではなく、「人に見せる前の恥ずかしいミスを削る一次フィルタ」として使うと役割がはっきりする。指摘をそのまま鵜呑みにせず、最終判断は自分で行う。

小さい修正ほど「レビュー依頼するほどでもないが不安」という場面が多いので、そういうケースで特に効果を感じやすい。
