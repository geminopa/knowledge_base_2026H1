# AIにテストケース案を出してもらう時のプロンプトの工夫

AIにテストケースを考えてもらう時、そのまま「テストケースを考えて」と投げると抜け漏れが多い案しか返ってこない。プロンプトの組み方で精度がかなり変わる。

- **仕様書やコードそのものを渡す**
  口頭要約ではなく、実際の仕様書の該当箇所やソースコードを貼って「この仕様に対して」と限定すると、的外れな案が減る。
- **観点のカテゴリを指定する**
  「正常系・異常系・境界値の3分類で出して」のように分類軸を先に指定すると、網羅性が上がり抜けに自分で気づきやすくなる。
- **入力パラメータの制約を明示する**
  「この項目は必須・最大20文字・半角英数のみ」など制約条件を伝えると、その制約特有の境界値ケース（21文字、全角混入など）まで提案してくれる。
- **出力フォーマットを指定する**
  「No / 前提条件 / 操作 / 期待結果 の表形式で」と指定すると、そのままテスト仕様書に転記しやすい。

AIが出したケースは「叩き台」として扱い、業務知識が必要な観点（お客様固有の運用ルールなど）は自分で追加する前提で使うのが安全。
