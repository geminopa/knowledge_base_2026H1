# バグ再現手順の書き方（再現性を上げるコツ）

「なぜか再現しない」と言われるバグ報告には共通点がある。書き方を少し変えるだけで再現率と対応スピードが上がる。

- **手順は番号付きで、1手順1操作にする**
  「〇〇画面で△△を入力して登録する」のように1行に複数操作を詰め込むと、どの操作が原因か切り分けづらい。「1. 〇〇画面を開く」「2. △△に'test'と入力する」「3. 登録ボタンを押す」のように分割する。
- **入力した具体的な値を書く**
  「不正な値を入れる」ではなく「半角スペースのみを入力する」のように、実際に使った値をそのまま書く。抽象的な表現は再現性を落とす最大の原因。
- **期待結果と実際の結果を分けて書く**
  「〇〇と表示されるはずが、△△と表示された」のように対比させる。事実（実際の結果）と期待（仕様上どうあるべきか）を混ぜて書かない。
- **環境情報を添える**
  ブラウザ・OS・実行環境（本番/検証/ローカル）・ログイン中のユーザー権限など、環境依存のバグは意外と多い。
- **発生頻度を書く**
  「必ず発生する」のか「10回に1回発生する」のかで、調査の優先度や見立てが変わる。

再現手順は「自分以外の誰かがそれだけ読んで同じ操作を再現できるか」を基準に書くと、抜け漏れに自分で気づきやすい。
